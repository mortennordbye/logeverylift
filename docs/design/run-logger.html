Run logger

Give the run exercise what the bike got: a planned view, a run mode that guides each step and saves it, Treadmill and Outdoor, step alerts, Garmin fill and the numbers a runner uses. Plus the edge cases a run has and a ride does not.

Version 4 · 2026-11-20 · for your yes. Nothing is built. Four reviews (code, running coach, screens, logic) checked version 1. The full build brief is docs/plans/run-logger.md, written so that a new session can build it with no chat history.

What the reviews changed

CodeIncline is a whole number in the database, and every step write sets it to null today. It becomes a decimal and a real step field. The step snapshot and the ride lookup are fixed to the bike, so both get the sport from the plan. Multisport Garmin files are read per part. Run cadence from Garmin is doubled, as on the Garmin pages.
Running coachEasy heart rate targets are caps: under the cap is a pass, so the summary shows no ↓ for an easy run. Run pace zones (Friel) are added. A heart rate step starts the belt at the slow end of its pace zone (zone 2 is 8.2 km/h for you), with "Adjust after 6 min". Treadmill strides become 30 s, because a belt takes 5 to 15 s to speed up. 1% incline counts as flat. Brick runs start on effort for 10 min. The threshold test gets checks, safety lines and a 7 day wait after illness.
ScreensThe belt − and + move into the target card and are larger, away from +1 min, so a wet finger cannot add time by mistake. Outdoor runs say that alerts are off, offer beeps with the screen on, and lock the controls against pocket taps. A strides block has its own screen. In a brick, the ride's done screen goes straight to Start run, with a live T2.
LogicEach step's end rule and belt speed are fixed at start, so a later Garmin correction cannot move the steps. A recovery never takes the stride speed. A late Lap tap at the end of a rep lands on the right step. A queued ride event cannot restart the ride while the brick run runs. Distance builds only while running, not while paused.
Added from the reviewsA surface choice outdoors (Road, or Trail or snow, where pace targets become heart rate). An optional reason when you end early. Pain links to the injury log.

What I found

Your run programs are plain sets"2 Base · Run" is one 75 min set at heart rate zone 2. The strides are only in the note. "Brick run · 40 min" is two plain sets (10 min zone 2, 30 min zone 3). No run program holds steps.
Play on a run does not run a clockPlay opens LogRunModal, which starts at 5 km (defaultDistanceM: 5000). For the 75 min set that gives 15:00 /km. This is the same failure as the 40 km bike guess.
The guided player is weak for a runIt opens only from a planned session of today, keeps everything in the phone's browser storage, saves nothing per step, sends no alerts and gets no Garmin fill.
Most of your runs are on a treadmill8 of your last 10 runs. Garmin says "Treadmill pace is not measured", so the watch distance is a guess. The belt speed you set on the machine is the true pace.
Run power is not a usable targetYour watch gives about 295 W on the treadmill (easy, HR 135) and about 375 W outside (HR 153). The numbers do not compare across modes, so this plan uses pace and heart rate, not power.
Your zones are guesses from GarminLTHR 180 and threshold pace 5:39 /km are Garmin estimates. Your easy treadmill run (HR 135 at 7:33 /km) is zone 1, which fits them, so it was simply easy. The run threshold test (step 8) replaces the guesses with a measured value.
Most of the bike build can be used againThe clock and event list, saving each step, the lap and time split for Garmin, and push all work for a run. The parts tied to watts need a run version: ±5 W, NP and IF, the outdoor target and the FTP test.

Run rules

  • One session machine. A run uses the same server session, frozen plan, event list and timeline as a ride. The table rides gets a sport column. No second table.
  • Belt events. On a treadmill each step starts with its planned belt speed. Each ± tap stores the new speed and incline with its time. Distance and pace come from these events.
  • Nothing to type during a run. Each step saves its time when it ends. After the run, one table, filled from the belt, with effort once.
  • A running session is frozen. AI changes to the program apply from the next run.
  • Brick. When a ride of a brick ends, its summary shows "Brick run next · Start run". The gap between ride end and run start is stored as the change time (T2).
  • Load. From pace and threshold pace. On a treadmill the incline counts (grade-adjusted pace), so an incline run no longer falls back to effort load. Outdoor uses Garmin's grade-adjusted pace from the stream. Each estimate is marked "est.".

What changes

  • Plain run sets of endurance users become steps, one time, keeping each zone. Every writer of run sets writes steps.
  • The run exercise shows the plan view, run mode, results and summary. The run ring in the workout list opens the run exercise, as the bike ring does.
  • The AI tools write and read the new run fields. A new step field incline for treadmill steps (the column inclinePercent exists).
  • The AI rewrites your run programs (93, 97, 102, 106, 95, 104): strides and race-feel parts from the notes become steps.
  • /planned/[id]/play opens run mode for a run-only program.

What does not change

  • The bike, swim and strength screens.
  • Your zones and thresholds, until you save a test result.
  • Garmin records the run. The app guides and logs.

Limits of a web app on an iPhone

  • No live pace or heart rate in the app: Safari has no Bluetooth, and GPS stops when the screen locks. The watch shows live numbers.
  • No sound with the screen locked. Push is the only alert then, and it can come a few seconds late.
  • No sending workouts to the watch (parked as E3).
